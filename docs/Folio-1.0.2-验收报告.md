# Folio Windows 1.0.2 验收记录

本版修复 Windows 更新检查的网络回退、状态处理和错误提示，并按反馈调整助手工具栏。macOS 保持 beta.3。

## 故障与修复

用户的 1.0.0 曾显示泛化的“检查更新失败”，随后在未修改真实客户端或系统代理的情况下成功查到 1.0.1。旧程序未保存具体更新检查错误，因此无法追溯那一次失败的准确原因。

已验证的缺陷是旧版检查元数据只尝试一次，下载阶段的代理回退不参与检查；连接错误、HTTP 错误与清单错误都显示同一条提示。隔离的正式 1.0.0 在失效代理下注入 `ERR_PROXY_CONNECTION_FAILED` 可复现相同提示，切换直连可成功查到更新。

1.0.2 保留系统网络优先，仅对连接、代理、DNS 或超时类错误重试一次直连，结束后恢复系统代理。HTTP 403/404 和清单格式错误不进行盲目网络重试；上游将网络错误包装成解析异常时，只分析错误前缀，不把 XML 正文中的文字当作网络错误。检查合并并发请求，重试过程不发布中间失败，恢复网络设置后才发布可下载状态。

错误提示区分连接、HTTP 状态和服务响应异常。界面数据目录的 `update-check.log` 仅记录时间、路径类型、结果、错误类别/代码及 HTTP 状态，不记录 URL、错误原文或凭据；超过 64 KiB 时保留近期记录。日志写入失败不阻止检查。

## 工具栏

- 移除“当前文献”及文献名称；问答和笔记图标由 17px 放大至 20px。
- 新建会话使用对称 SVG 加号，32×32px 按钮内居中，固定在工具栏最右侧，保留 8px 内边距。
- 会话占用中间空间，窄栏多会话仅在会话条内横向滚动；从笔记进入会话、新建、删除、流式生成与历史保存沿用。

## 验证

`npm run build:ui`、主进程语法检查及 `npm run test:updates` 通过。更新检查合同覆盖默认成功、网络失败转直连、两种路径都失败、HTTP 403/404、包装的连接错误、清单错误、恢复代理失败及并发请求。一次未修改缓存模块的测试出现 Windows `EPERM rename`，完整重跑通过，首次失败日志保留在本地。

正式 Windows 程序使用独立数据目录查询公开 GitHub：默认连接出现 `ERR_CONNECTION_CLOSED` 后，自动直连成功并恢复系统代理，期间界面没有出现中间 error。还使用真实 Electron HTTP transport 与环回 generic 清单服务，将 updater session 设置为失效代理，验证代理错误后直连成功、显示未来版本 available、恢复系统代理且没有下载资产。联网测试期间也出现过两种路径都不可用的情况，新程序正确提示连接失败并恢复代理；这类错误仍取决于当时网络，补丁不保证绕过所有网络阻断。以合成未来版本和 HTTP 403 注入生产 updater，验证并发检查合并、恢复后才出现 available，以及 HTTP 错误不重试。

最终正式包的 GUI 协议/会话回归通过：470px 和 280px 栏宽下无文献名称，加号贴右且 SVG 与按钮中心误差不超过 0.5px；三个会话在窄栏内滚动，工具栏不溢出。浅/深主题、hover、模式切换、从笔记新建会话、流式回答及重启保留聊天均通过。

正式包的 266 个前端文件与构建输出一致，main/preload/updater 与源码对应，未含验收 bootstrap；后端 SHA-256 为 `a058544ac15ed317ff1160f1b3b91a033237170685ef5035ee6f830c1fe3128a`，与 1.0.0 相同，3313 个 PDF 引擎资源保持一致。本版未修改 PDF 圈选与标记代码；详细几何回归见 [1.0.1 记录](Folio-1.0.1-验收报告.md)。未重复执行未修改后端的整套测试。

正式安装包的差分重建通过，重建 SHA-256/SHA-512 与候选一致，没有全量下载尝试。真实 electron-updater 使用正式 blockmap 和安装包，GitHub/代理 URL 映射到环回服务：

隔离 NSIS 从 1.0.0 安装、检查、取消下载、重试、重启安装并自动启动 1.0.2，通过。原文/中文/双语 PDF 哈希、分类、笔记、批注、主题、模型配置与合成凭据状态保留；当前安装包缓存校验及去重通过。随后正常关闭并重新打开也通过。包装使用独立 appId、安装/数据/凭据目录及 NSIS 缓存，生产文件逐字节审计通过，假凭据已清理；未升级用户正在运行的真实客户端。
