# 阅川 · Folio 0.11.0

这是 Windows 桌面应用，可在同一窗口的标签页中阅读中文 PDF、原 PDF 或左右双语 PDF。文献库固定保留在一个标签；同一篇文献只打开一个阅读标签，关闭标签不会删除文献。每篇文献的页码、缩放、阅读模式、聊天、草稿和模型彼此隔离，切换标签时保留。文献进度与聊天会持久化；重新启动时恢复仍可阅读的标签。导入后，应用用随包提供的 PDF2zh-Next/BabelDOC 引擎生成真正的中文 PDF 和左右双语 PDF。译文替换原文字区域，中文换行和字号会按版面适配；页面尺寸、图像与图表位置会保留，但不承诺逐字像素一致。默认阅读左右双语 PDF，页面数与原文一致，不会把双语页变成两倍页数。

阅读器按连续页面纵向滚动，页码与阅读进度随滚动保存；页码、引用链接和重启恢复都落到对应页面。阅读工具栏留在滚动区外。PDF共用一次加载的文档，按视口邻域绘制页面，并以至少2倍像素采样显示；远处页面回收画布位图以控制内存。每页按自己的尺寸保留滚动高度。放大 PDF 后可在页面滚动区横向移动到左右边缘，滚动容器和工具栏仍保持原宽度。

0.6.0 加入流式问答，回答文字会随服务返回逐步显示。若服务商发送了真实思考字段，阅读器会另行显示并保留思考过程；未发送时不会伪造。停止生成会关闭当前流式请求，已收到的部分内容会标为未完成且不会带入后续模型上下文。全文总结也可停止并从整篇原文重新开始。框选 PDF 文字不会自动写入聊天输入框。

阅读标签中的导航、PDF 和 AI 助手三栏可分别拖动调整宽度；导航与 AI 助手可从顶部独立隐藏或显示。布局和每篇文献的当前页在切换标签及应用重启后保留。隐藏 AI 助手或切换到其它阅读标签时，正在进行的流式回答和输入草稿仍保留；关闭文献标签会停止该文献自己的活动回答，不影响其它标签。

阅读器右侧可在 AI 助手和笔记之间切换。每篇文献有独立阅读笔记，输入会先保留为本地草稿并延迟保存，也可手动保存；保存失败或关闭标签后重新打开仍可恢复草稿。选择同一 PDF 页内的文字后可添加四种低饱和色高亮或批注，批注可编辑和删除，普通高亮也可删除；阅读笔记按每篇文献独立保存，高亮和批注按 PDF 版本及页码分别保存，点击列表位置会切换到对应版本并跳页。数据保存在本机 SQLite 数据库，不发送给 AI，不修改原 PDF；高亮和批注以页面归一化坐标覆盖显示，缩放和窗口尺寸变化时会随页面对齐。

AI 助手顶部仅保留当前文献，模型名称与下拉箭头紧邻显示在输入框底部，可直接展开切换。模型添加仍在设置页完成。答案字号为 18px，提问输入为 16px；联网搜索和发送/停止与模型选择分开放置，窄栏下仍可操作。

## 安装与首次使用

运行 `dist/installer-0.11.0/阅川-Folio-0.11.0-安装程序.exe` 安装。安装向导默认使用 D 盘目录，允许修改位置。解包版也可从 `dist/installer-0.11.0/win-unpacked/` 启动，但必须保留完整的 `win-unpacked` 文件夹。

PDF 引擎、Python 运行时、字体和布局模型都包含在安装包中，使用时不需要另装 Python、打开 `.py` 文件或启动命令行服务。首次生成 PDF 时，应用会把随包资源复制到数据目录中的 `.pdf-engine-home`；复制期间任务会显示进度。翻译需要联网：免费的 PDF 翻译服务会收到文献标题和正文文本，服务不可用时任务会报错供重试，不会改用付费 AI。

导入文献会在本地库中保存副本。相同 SHA-256 的文件会合并；同名但内容不同的文献分别保存。只有引擎成功生成并通过页数、页面尺寸和中文内容检查后，阅读器才会开放。0.2.0 中已标记完成但没有真实中文 PDF 的条目会自动排队补生成。处理中的文献可以暂停和恢复；已经生成的 PDF、阅读进度和聊天会持久保存。

文献详情提供中文标题重命名和删除。删除操作会确认一次，只删除本地库副本、已生成的中文/双语 PDF、聊天和阅读进度；最初选择的源文件不修改、不删除。

文献库左侧显示单层分类文件夹，每个分类自动使用持久颜色标记。可创建、重命名和删除文件夹，将文献移动到文件夹或未分类，并按分类查看和搜索。导入时会归入当前文件夹；重复文件仍指向已存在条目，不会改变其分类。删除文件夹只会把其中的文献移到未分类，不删除文献或 PDF。

## AI 问答

问答和总结可选配置支持 OpenAI Chat Completions tools 的服务和模型。在“AI 问答与总结”填写服务商提供的完整 API URL、模型名称和 API Key，URL 会原样用于请求。API Key 由本地后端保存在 Windows 凭据管理器中，设置页不会回读显示。你配置的 AI 服务仅用于阅读原文的问答、总结和引用，不会用于 PDF 翻译；使用费用按服务商规则计算。

阅读窗口显示当前模型，并允许每篇文献单独切换模型；常用模型可手动添加。设置页可直接用当前 AI API URL 获取模型列表，默认按常见 OpenAI 地址规则推导 `/models`，不会更改聊天请求地址；受限服务使用已保存或本次输入的 Key，公开服务可以匿名查询。服务使用其他模型列表地址时，可展开高级选项手动填写。读取结果只供勾选后添加，不会自动把整个目录加为常用模型。阅读器的“联网搜索”默认开启，模型可以在问题需要外部资料时调用免 Key 的 Bing RSS 搜索；关闭后搜索工具会从本轮请求中移除。搜索只发送短关键词，不会发送文献全文或 AI Key，也不会自动打开搜索结果网页。

AI 首轮只接收文献页数和近期对话，不会自动发送正文。模型可按需调用 `read_paper` 查询当前文献的原文片段；全面总结时调用 `summarize_paper`，工作台会将完整可提取原文和页码标记在一次请求中发送给所选模型，不截断、不分块。服务拒绝过长输入时会显示失败原因并允许重试；普通无关问题不会读取论文。服务或模型不支持 Chat Completions tools 或流式接口时会明确报错，不会退回每次注入全文。新生成回答按 LaTeX 规则使用 `$...$` 行内公式和独立行 `$$...$$` 块公式，并支持标题、列表、表格、粗体和代码；已有聊天记录不会自动改写，需重新提问或生成答案。原始 HTML 不执行，远程图片不加载，只显示图片说明。页码引用经本地来源校验后可点击跳转；网页搜索引用会列出来源，并由系统浏览器打开。

## 本机数据与限制

默认数据目录为 `D:\个人工作台\data`，含原始 PDF 库内副本、生成的中文与双语 PDF、SQLite 数据库、聊天、笔记、批注及阅读进度。可在设置页选择新的空文件夹；确认后应用会停止任务、复制并逐文件校验文献数据，成功才切换配置并重启。旧目录保留作备份，应用不会自动删除它。AI 凭据身份和 Electron 界面设置保持原样，不随文献库迁移；安装位置也不会改变。卸载应用不会自动删除数据目录。完整生成的 PDF 和副本都会占用磁盘空间。

扫描件或存在可见内容但无法提取正文的页面目前会阻止完成，并显示页码诊断；应用没有单独 OCR 步骤。当前不会翻译表格单元格里的文字，图片中的文字和公式保持原样。双栏、照片与矢量图表的结构保留已用合成文献验证，但不同论文的公式、跨页图表和复杂排版仍应实际检查译文。

## 从源码构建

在 D 盘的 `D:\个人工作台` 项目根目录中准备 Node.js 和 Python 3.12。所有项目依赖、下载缓存、临时文件和构建产物都放在 D 盘项目目录下：

```powershell
Set-Location 'D:\个人工作台'
New-Item -ItemType Directory -Force .cache\npm, .cache\electron, .cache\electron-builder, .cache\pip, .cache\build-temp | Out-Null
$env:npm_config_cache = Join-Path $PWD '.cache\npm'
$env:ELECTRON_CACHE = Join-Path $PWD '.cache\electron'
$env:ELECTRON_BUILDER_CACHE = Join-Path $PWD '.cache\electron-builder'
$env:PIP_CACHE_DIR = Join-Path $PWD '.cache\pip'
$env:TEMP = Join-Path $PWD '.cache\build-temp'
$env:TMP = $env:TEMP
$env:TMPDIR = $env:TEMP
py -3.12 -m venv .venv
npm install
.\.venv\Scripts\python.exe -m pip install -r .\backend\requirements.txt
npm run dist
```

`npm run dist` 会构建界面、本地服务和随应用运行的 PDF 翻译引擎，然后用本地 Electron 生成 NSIS 安装程序。PDF 引擎依赖固定在 PDF2zh-Next 2.9.0 和 BabelDOC 0.6.2；首次创建 `.venv-pdf-engine` 时会安装其构建依赖。构建产物位于 `dist/installer-0.11.0/`。引擎及许可证/对应源代码随包位于 `resources/pdf-engine/`、`resources/pdf-engine-source/`，许可证说明见 `resources/THIRD-PARTY-NOTICES.md`；两项引擎使用 AGPL-3.0。PDF.js 固定为已修复安全问题的 6.2.108，KaTeX 固定为已修复安全问题的 0.19.0。开发调试可运行 `npm run dev`，这不是交付运行方式。
