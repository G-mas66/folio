# Folio Windows 1.0.4 验收记录

本版修复标题翻译遇到短暂限流便立即终止导入的问题，并将邮件草稿反馈改为应用内输入框提交。Windows 版本为 1.0.4；macOS 仍为 0.14.0-beta.3。

## 翻译问题与修复

截图的文案精确对应 FreeTranslationClient 收到 HTTP 429 的分支。导入流程在中文标题为空时先翻译标题，旧实现一次 429 就把文献置为 error，尚未启动正文 PDF 引擎。右键翻译与标题翻译使用同一客户端、服务地址和请求格式，右键成功并不能排除另一时刻的限流。

以截图中的公开英文标题及合成句子对照真实服务：标题返回 200 和中文译文，两秒后的合成句子返回 429。证据支持服务间歇限流和应用缺少恢复处理，不能据此称服务永久故障，也不能承诺持续限流时一定完成。

免费客户端现在在 429 后最多重试两次。读取 Retry-After 秒数或 HTTP 日期；没有该头时等待 4 秒、8 秒；要求等待超过 30 秒时不提前自动重发。标题与右键请求共用 QPS 和冷却窗口，已排队请求也会重新检查冷却，等待中响应暂停。持续限流保持明确可重试的错误，其他错误不盲目重试。未引入收费 AI 回退，PDF 引擎未修改。

旧模块对照在新增的标题与选中文本恢复测试中因首个 429 报错；修复后通过。后端完整回归 141 项：140 通过，1 项 Windows 不适用跳过。

## 应用内反馈

点击意见反馈打开输入框，正文必填，联系方式选填；发送中锁定输入与按钮，失败保留文字，可重试。固定 FormSubmit HTTPS 地址通过主进程 Node fetch 提交用户输入、应用版本和固定公开来源标识；校验窗口、输入长度和 12 秒超时。不自动打开邮箱，不发送文献、日志或凭据。

真实接入证明 FormSubmit 还要求来源 Referer，仅 _url 不足；正式包测试又发现 Electron net.fetch 返回 ERR_BLOCKED_BY_CLIENT，因此本版反馈使用已验证的 Node fetch。最终正式程序的真实 UI / preload / main IPC 提交返回 HTTP 200、success true，且未打开外部应用。用户另提供收件截图，确认首条开发反馈正文已送达。普通提交成功提示只表示服务接收；首次邮箱激活属于收件端操作。
