# Folio Windows 1.0.3 验收记录

本版增加官方 API 备用更新检查、邮件反馈和 Windows 卸载入口，移除主题切换按钮前的多余加号。macOS 保持 beta.3。

## 更新检查

用户已安装的 1.0.2 日志记录了系统网络连接中断、直连超时，两条路径均失败。随后隔离复测同一网络的原检查路径又成功；尚不能准确确定间歇故障的底层原因，也没有证据支持固定关闭 HTTP/2 或写死本机代理端口。

1.0.3 保留系统网络优先、连接错误后直连重试及代理恢复。两次均因连接类错误失败时，使用 Node 原生 fetch 访问 GitHub 官方 Releases API，再读取官方资产 API 的 `latest.yml`。验证资产长度与 SHA-256、正式版标签与清单版本、安装包名称和 SHA-512；保留 electron-updater 的版本判断、事件、下载校验、取消及安装流程。仅 Folio 官方稳定通道启用此备用路径，HTTP 权限/不存在错误和无效清单不会触发盲目重试。

检查仍合并并发请求，回退过程中不提前发布失败或可下载状态。备用检查结束后恢复原 provider 方法；脱敏日志增加 `github-api` 路径，不记录请求 URL、Key 或原始错误正文。不改变系统代理配置，不跳过 TLS 或安装包摘要校验。所有路径均不可达时仍会失败；新代码不能修复尚未升级的旧进程。

## 反馈与卸载

- 移除主题、护眼模式和设置按钮前的多余加号；保留导入、创建文件夹和助手新建会话。
- 左侧“打开文献目录”下方增加“意见反馈”，通过固定 `mailto:1791913726@qq.com` 打开邮件草稿。用户自行编辑发送，需要系统配置可用的邮件应用，无需 GitHub 账号。
- Windows 安装版在“设置 → 应用卸载”提供入口，先确认，再打开安装目录中明确命名的 NSIS 卸载程序。取消不显示错误；不传递静默卸载或删除应用数据参数。
- 卸载前检查文献、凭据、界面数据目录；原始路径或解析 junction 后的真实路径位于安装目录内时均阻止卸载，路径无法确认也不继续。迁移、更新安装或下载期间不能启动卸载；确认对话框返回后再次检查。正常卸载保留安装目录外的文献库及凭据。

## 验证

`npm run build:ui`、`npm run test:updates`、`node review/test_app_actions.cjs` 和主进程语法检查通过。API 测试覆盖真实 NsisUpdater/GitHubProvider 的可更新和无更新、正式通道限制、HTTP 不回退、清单摘要/版本/结构/SHA-512 校验、Node 连接错误分类。应用操作的 10 项测试覆盖邮件地址、卸载器定位、路径边界与 junction、取消、确认、状态复验和启动错误；shell/dialog 使用 stub，未卸载用户应用或发送邮件。

正式包的 GUI 验证通过：多余加号消失，其余主题、护眼、设置、创建文件夹和导入按钮保留；真实 preload/main IPC 将反馈交给固定邮件地址，测试仅在外部 shell 边界记录请求。未安装的 win-unpacked 正确禁用卸载，实际 IPC 在显示确认或启动程序之前拒绝。另以合成 IPC 结果验证已安装状态下的取消、启动成功、错误提示、不可用状态和非 Windows 隐藏。没有打开真实邮件或卸载程序。

包内 266 个前端文件与构建输出一致，9 个主进程模块与源码一致，未含验收 bootstrap。后端 SHA-256 为 `a058544ac15ed317ff1160f1b3b91a033237170685ef5035ee6f830c1fe3128a`，与 1.0.0 相同；3313 个 PDF 引擎资源保持一致。应用身份、可执行文件名、凭据身份和更新通道沿用。本版未修改 PDF 标记几何或后端，因此未重复未修改后端的整套测试。

最终生产 ASAR 的真实更新 IPC 联网验收通过：连续三次原路径查询当时的公开 1.0.2，均显示无更新。随后只注入原 Atom 请求的连接错误，真实 1.0.3 客户端通过官方 API 和资产 API 成功得到无更新；临时将客户端版本设为 1.0.1 后，同样回退取得真实 1.0.2 元数据并显示可更新。两种回退状态分别为 checking → not-available / checking → available，没有中间 error，provider 方法及版本均恢复。此处版本 1.0.1 是测试注入，官方元数据来自真实联网请求；未下载资产或升级用户客户端。

隔离 NSIS 从 1.0.2 安装、检查、取消下载、重试、重启安装并自动启动 1.0.3，通过。原文/中文/双语 PDF 哈希、分类、笔记、批注、主题、模型配置及合成凭据状态保留；正常关闭并重新打开、当前安装包缓存校验与去重也通过。验收使用独立 appId、安装目录、数据目录、凭据身份和 NSIS 缓存，未触碰正在运行的用户进程；假凭据已清理。包装与生产 ASAR 文件逐字节一致（仅验收入口及包元数据按隔离要求调整）。

正式 1.0.2 → 1.0.3 安装包差分重建通过：真实 NsisUpdater 使用正式 blockmap，GitHub/代理资产 URL 映射到环回服务，9 次 Range 请求，含清单及 blockmap 总计传输 13,290,194 字节，较整包节省 97.3662%。重建的 SHA-256/SHA-512 与正式候选一致，没有全量下载尝试。
